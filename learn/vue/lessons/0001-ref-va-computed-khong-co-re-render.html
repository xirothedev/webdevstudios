ref & computed: không có re-render

15 phút · một thắng lợi: giải thích được vì sao code Vue dưới đây chạy được trong khi bản React tương đương thì không

1. Kiến thức nền (5 phút đọc)

Trong React, component là một hàm bị gọi lại mãi: mỗi setState → chạy lại entire function → JSX mới → diff. Đó là lý do mọi thứ React phải "đóng băng": snapshot của count, deps array của useMemo, stale closure.

Vue ngược lại: setup chạy đúng một lần. Bạn khai báo state bằng ref() — một object có .value được bọc bằng Proxy. Khi template hay computed nào đọc .value, Vue ghi nhớ đúng chỗ đó. Khi bạn ghi, Vue chỉ cập nhật đúng chỗ đã đọc. Không có vòng render, không có hàm chạy lại. (Reactivity in Depth) 

// React — hàm chạy lại sau mỗi click
const [count, setCount] = useState(0);
const double = useMemo(() => count * 2, [count]);
setCount(count + 1);          // phải tạo giá trị mới

// Vue — setup chạy 1 lần, suốt đời component
const count = ref(0);
const double = computed(() => count.value * 2);
count.value++;                // mutate thẳng, hợp lệ

Ba hệ quả phải khắc:

  • computed không cần deps array — nó biết phụ thuộc vào gì vì hàm của nó vừa đọc count.value ngay bên trong. Đọc phải .value thì mới bị track. (Đó là cả cơ chế, không phải quy ước.)
  • Template tự unwrap — trong <template> viết {{ count }}, không cần .value. Trong script thì .value là bắt buộc — quên là mất reactive, không báo lỗi.
  • Không có stale closure — count.value lúc nào cũng là giá trị hiện tại, vì chỉ có một object.
Đọc tiếp nguồn chính (bắt buộc, 10 phút): Vue docs — Reactivity Fundamentals, mục Declaring Reactive State + Computed Properties.
